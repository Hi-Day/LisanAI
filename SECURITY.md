# Security Policy

## Supported versions

Security fixes are prioritized for the latest version on the default branch. Until tagged releases are published, there is no separate long-term-support branch.

## Reporting a vulnerability

**Please do not report suspected vulnerabilities in public issues, pull requests, discussions, or social media.**

Use GitHub's **Private vulnerability reporting** feature for this repository if it is enabled. If it is unavailable, contact the repository maintainer through a verified private channel listed on the maintainer's GitHub profile and ask for a secure reporting route. Do not include exploit details or sensitive student data in a public message.

Please include, where safe:
- A concise description and potential impact.
- Affected version, commit, endpoint, or configuration.
- Minimal reproduction steps or a proof of concept that does not access real user data.
- Any suggested mitigation.

Please allow time for triage and a fix before public disclosure. Do not test against production systems or data without explicit authorization.

## Sensitive data

Never include API keys, session cookies, student records, audio recordings, or other personal data in a report. Revoke and rotate any credential that may have been exposed.
