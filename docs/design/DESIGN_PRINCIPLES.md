# LisanAI Design Principles

## Purpose

Define the product-level principles that guide every visual and UX decision in LisanAI.

## North Star

> LisanAI should feel intelligent without feeling intimidating.

It should be:

- Friendly enough for students.
- Professional enough for teachers.
- Trustworthy enough for schools.
- Modern enough to feel genuinely AI-native.
- Clear enough that users rarely need to ask "what do I do next?"

## Core Principles

### 1. Clarity over density

Prefer fewer, clearer elements over displaying every available metric.

### 2. One primary action

Each context should have one visually dominant action.

### 3. Progressive disclosure

Expose complexity when it becomes relevant. Do not make first-time users understand the entire assessment system.

### 4. AI should assist, not dominate

AI should explain, recommend, summarize, and accelerate work. Users remain in control.

### 5. Human judgment remains visible

Assessment is consequential. The UI must distinguish AI-generated results from teacher-reviewed or verified results.

### 6. Every action has feedback

Important actions must provide clear loading, success, failure, or progress feedback.

### 7. Preserve user work

Never unexpectedly discard entered assessment configuration, answers, recordings, or drafts.

### 8. Make state visible

Users should be able to understand whether an assessment is draft, published, in progress, submitted, processing, verified, or failed.

### 9. Use color semantically

Follow COLOR_SYSTEM.md. Do not introduce arbitrary colors for individual components.

### 10. Calm professionalism

Fun comes from controlled color, friendly microcopy, motion, illustration, and interaction—not visual noise.

## Experience Personality

LisanAI should communicate:

- Curious
- Encouraging
- Intelligent
- Human-centered
- Trustworthy
- Efficient

Avoid:

- Corporate stiffness
- Childish gamification
- Excessive gradients
- Visual clutter
- AI hype language
- Ambiguous controls

## Decision Rule

When two UI solutions are both technically valid, prefer the one that:

1. reduces cognitive load,
2. makes the next action clearer,
3. exposes important state,
4. preserves user control,
5. requires less explanation.
